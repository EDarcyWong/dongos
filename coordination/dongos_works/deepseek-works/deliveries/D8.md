# D8 交付说明 — mm.phys_buddy 物理页伙伴分配器

日期：2026-10-17。负责人：DeepSeek。

## 新增文件

- `kernel/mm/phys_buddy.dg` — 单 arena 伙伴分配器（order 0..10，4 KiB..4 MiB）。
- `kernel/mm/errors.dg` — `mm.errors` 共享错误码（0x0200_0001..0x0200_0008）。
- `kernel/mm/phys_buddy.md` — 模块说明。
- `tests/test_phys_buddy.py` — 独立 C 参考模型测试（ELF64/COFF + debug/release 原生）。

## 实际命令

```text
python -m unittest tests.test_phys_buddy -v
```

结果：2 项测试通过（模块 ELF64+COFF 组装；debug/release 两模式的 C 宿主探针）。

## 测试数量/结果

- `test_module_compiles_and_assembles`：phys_buddy.dg（连同 mm.errors）在 ELF64、win64 组装，通过。
- `test_native_buddy`：debug/release 各一次，宿主执行：
  - 布局经 `sizeof/alignof` 导出核对（不猜字段偏移）。
  - 独立 C 位图/占用模型交叉核对每次 alloc 的块均已发布、无重叠、正确对齐，及 `free_pages` 精确统计。
  - 覆盖 0～10 全阶（每个阶用独立 arena 分配单块）、耗尽、拆分、乱序释放后恢复、holes 阻止合并、多实例隔离。
  - 非法 page_count、元数据不足、重复 init、重叠发布、OOM、无效阶、非对齐/错阶/越界/未分配释放，逐项核对错误码。
  - 2^20 页 arena（C 堆元数据）、4 GiB 与 16 GiB 以上基址、u64 末端溢出、零长度发布。
  - 4000 轮固定种子随机 alloc/free 与位图参考模型逐项一致。

## 限制

- 未接入现有活动内核，未实现页表、对象缓存、多 arena、NUMA 或 UEFI 内存图解析；未清零实际页面。
- 单线程（或调用方持锁）；`free` 不提供代际检测，陈旧地址的所有权由调用方负责。
- 未改动编译器、语言规格、构建入口、P0/P1 或 Codex 维护的文件；未创建提交/推送。
