## 测试数量/结果

- `test_module_compiles_and_assembles`：x86_64.dg 与 x86_64.asm 分别在 ELF64、win64 组装，全部通过。
- `test_native_arch`：debug/release 各一次，宿主执行：
  - `CpuId` 布局核对（大小 16、align 4、字段偏移 0/4/8/12）；
  - `read_tsc` 两次读取单调不减；
  - `cpuid(0)` 厂商串核对（Intel/AMD/Hygon/VIA 或 12 字节可打印 ASCII）；

## 限制

- `read_tsc` 未做序列化屏障，契约已写入文档；`cpuid` 的寄存器保留只在宿主已验证，真机差异不在本批范围。
- 未改动编译器、语言规格、构建入口或 Codex 占用的文件；未创建提交/推送。

## 返修记录（Codex 审查后）

审查发现 `test_std_arch.py` 的 C 探针把 `arch_regcheck` 声明为普通 C 函数，Windows 下默认按 Microsoft x64 调用；而 NASM 观察器按 SysV 编写并在调用 `dg_arch_cpuid` 前清零 RDI/RSI，违反了 Microsoft x64 对 RDI/RSI 的非易失保存要求。

修复：将该声明改为显式 SysV ABI，`extern int DG arch_regcheck(void);`（`DG` 即 `__attribute__((sysv_abi))`），与观察器的 SysV 约定一致。

验证：

```text
python -m unittest lang.tests.test_std_arch -v
Ran 2 tests in 0.916s
OK
```

debug/release 两模式原生探针及 ELF64/COFF 组装均重新通过。状态更新为“已修正，待 Codex 复验”。
