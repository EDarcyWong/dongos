# `bootstrap.guest_source_path` — 客体源码相对路径的只读词法门禁

本模块为后续“受限源码读取”提供**纯词法**边界：校验一个逻辑根标识与一条相对 UTF-8
路径，并在调用者输出缓冲区中逐字节发布该路径。它不分配内存、不访问文件系统、不解析
根目录、不拼接根字符串、不跟随符号链接，也不授予任何权限。

## 接口

```dong
import bootstrap.guest_source_path as path_gate;

const OK:u64=0;
const INVALID:u64=1;
const CAPACITY:u64=2;

const ROOT_SOURCE:u64=0; // 客体源码根
const ROOT_INCLUDE:u64=1; // 只读 include 根
const ROOT_LIMIT:u64=2; // 合法根标识为 0..ROOT_LIMIT-1
const MAX_PATH:usize=4096; // 相对路径总字节上限（不含 NUL 终止符）
const MAX_SEGMENT:usize=255; // 单个 '/'-分隔段的最大字节数

pub fn lexical(path:[]const u8)bool;
pub unsafe fn validate(root:u64,path:[]const u8,out:[]u8,written:*usize)u64;
```

`validate` 的输入依次为：根标识、相对路径只读切片、调用者可写输出缓冲区、以及
`written` 计数指针（要求 8 字节对齐、8 字节范围不环绕）。

输出缓冲区按**完整声明区间** `[out.ptr, out.ptr+out.len)` 校验，而不是只校验最终写入的
`path.len` 前缀：该区间端点不得回绕，且必须与路径区间、与 `written` 的 8 字节区间**在任意
偏移上都不重叠**。`out.len==0` 是合法的空区间（随后按容量不足处理）。因此把路径或
`written` 放在输出缓冲区未使用的尾部、或声明一个端点回绕的巨大 `out.len`，都会在写入前
被 `INVALID` 拒绝，不会破坏 `written` 之外或前缀之外的调用者字节。

## 接受的路径

- 根标识必须为 `0..ROOT_LIMIT-1`；未知标识返回 `INVALID`。根标识只是调用者受限打开
  策略的选择子，不是宿主路径，也不能单独证明任何访问权。
- 路径非空、总字节数 `1..=4096`，按 `/` 分段，每段 `1..=255` 字节。
- 每一段必须是**严格最短形式 UTF-8** 的完整标量序列；因此中文、日文、emoji 等合法
  多字节文件名被接受，超长编码、代理项、`>U+10FFFF`、被截断序列被拒绝。
- 仅接受相对形式：无前导 `/`、无尾随 `/`、无空段（`a//b`、`/a`、`a/` 均拒绝）。
- 拒绝恰好为 `.` 或 `..` 的段，因而 `../x`、`a/../../x`、`a/./b` 均拒绝；`...`、
  `.hidden`、`a./b` 是普通段，接受。
- 拒绝任何 NUL（`0x00`）、ASCII 冒号（`0x3a`）和反斜杠（`0x5c`）字节：冒号覆盖
  Windows 盘符与 NTFS 数据流写法，反斜杠覆盖 Windows 分隔符与 UNC 形式；POSIX 绝对
  路径由前导 `/` 或空首段拒绝。
- 合法路径**按原字节发布**：不大小写折叠、不做 Unicode 规范化、不截断、不做任何
  “根字符串前缀比较”。`src/main.dg`、`src2/main.dg`、`src-evil/main.dg` 都是三个
  互不相关的相对路径；目录边界只来自段结构，不来自字符串前缀。

“最大字节数”是明确契约：`MAX_PATH=4096` 针对完整相对路径，`MAX_SEGMENT=255` 针对
单个段；两者都按字节计，不按码点计。

## 结果与原子性

| 结果 | 含义 | 输出 |
| --- | --- | --- |
| `OK` | 路径合法且输出容量足够 | `out[0..len]` 为路径原始字节，`*written=len` |
| `INVALID` | 未知根、非法描述符/别名，或路径词法非法 | 不写任何字节，不更新 `*written` |
| `CAPACITY` | 路径合法、`out` 描述符合法且不别名，但 `out.len < path.len` | 不发布半条路径，不更新 `*written` |

检查顺序固定为：`written` 描述符（非空、对齐、范围）→ 根标识 → 路径长度与指针范围 →
词法校验 → `written` 与路径别名 → **完整 `out` 声明区间**（端点不回绕、与路径和
`written` 均不重叠）→ 容量。因此非法路径即使输出缓冲区为空也返回 `INVALID`，不会被误报成
容量不足；描述符本身非法（含端点回绕、与路径或 `written` 别名）时也优先返回 `INVALID`，
不会因为容量不足被降级成 `CAPACITY`。只有描述符完全合法时，容量不足才返回 `CAPACITY`，
且绝不检查或写入 `out` 的任何字节，更不会留下部分路径。所有失败都发生在首次写 `out` 或
`*written` 之前，调用者缓冲区与尾部 canary 保持原样。

## 明确不负责的部分

本模块只证明“字节形态是某个逻辑根下的相对路径”。它**不**证明目标存在、可读、未被
符号链接/硬链接替换、未跨挂载点，也不证明路径真的落在根目录内。调用者必须：

1. 自己保存根目录句柄（或等价能力），只通过 `openat`/`O_NOFOLLOW` 一类受限 API 打开；
2. 对符号链接、`..` 以外的重解析点、挂载点和真实文件类型做运行时检查；
3. 按自己的权限模型授权读取。

换言之，单靠本模块的校验不能授予文件系统权限；把 `OK` 当作“已获准读取”是调用方的
安全缺陷。

## 复用

严格 UTF-8 校验直接复用主线 `lang/std/core/utf8.dg`（`module core.utf8`，`pub fn validate`），
本模块只通过 `import core.utf8 as utf8;` 调用它，不复制其解码器。构建期需要同时提供本
模块根与 `lang/std` 根；测试即以此为根编译 debug/release 两个真实产物。

## 验证

`pool-works/tests/test_guest_source_path.py` 使用真实 Dong 编译产物（debug/release、
ELF64/Win64 汇编两条格式）驱动原生 C 夹具，覆盖：相对/UTF-8/中文/emoji、同名前缀兄弟
目录、绝对路径与盘符/冒号/反斜杠/NUL、空段与 `.`/`..`、段长 255/256、总长 4096/4097、
严格 UTF-8 失败、精确容量与容量不足、失败原子性与尾部 canary、只读输入页、根标识边界，
以及 5 个实际编译的坏实现负控（放行 `..`、跳过 UTF-8 校验、校验前写入、截断发布、拒绝
多字节名），每个坏实现都必须在两模式下被断言拒绝。

另有一个独立的原生描述符探针，直接链接同一份 Dong 产物，覆盖完整 `out` 声明区间的三个
边界：`written` 位于 `out` 未使用尾部、路径位于 `out` 未使用尾部、`out.len` 端点回绕
（此时 `out.ptr` 仍是真实可写缓冲、`op+path.len` 仍在范围内，正是只检查写入前缀会放行的
情形）。三者都必须返回 `INVALID` 且调用者字节（含 `written` 槽位与尾部 canary）完全不变；
探针同时保留一个合法 `OK` 基线，防止“全部拒绝”的假通过。把实现退回“只检查
`out[0..path.len)`”的编译负控必须被这三个用例逐个拒绝。测试同时校验输入源码 SHA 稳定，
并在 `build/GUEST1/run-*/summary.json` 保存来源 SHA、产物 SHA 和逐组结果。
