## 实现

`emit(module_name, item_name, condition, yes_block, no_block, out, written)` 生成可调用函数 `u64 f(u64 lhs, u64 rhs, u64 yes_value, u64 no_value)`。按任务书顺序实际调用已集成组件：CR3 符号 + `:\n`，CR11 `prologue(32,0)`，C37 捕获 4 个 kind0 参数到 `[rbp-8/-16/-24/-32]`，CR12 以 width64、unsigned 把 lhs 装 rax、rhs 装 rcx，C22 `emit(condition, rax, rcx)`，固定 `test rax, rax\n`，CR10 `emit(NE, yes, no, yes)`（yes 是真实落入，假时 `je` 到 no），CR18 yes 标签 + C42 `emit(8, 32, 0, 24, 0)`，CR18 no 标签 + C42 `emit(8, 32, 0, 32, 0)`。两个块各有完整尾声和 `ret`。

预检顺序：written（非 NULL、8 对齐、端点）→ 两个名字与 out 的端点/NULL → written 与 out 别名 → written、out 与两个完整名字的别名 → 名长 1..64 → condition 0..9 → block 非 NONE 且不同。全部是 INVALID，并且都在容量判断之前；名字之间允许重叠。

所有组件写进 1024 字节局部 scratch，每段固定分配：266+2+64+128+64+64+48+14+48+32+128+32+128 = 1018 ≤ 1024。实际最长输出 698 字节（64/64 名字、两个 20 位 block），测试按精确值断言。组件任何非 OK 都按 INVALID 返回，此时 out 没被碰过。最后才比较容量并一次性发布 out 和 `*written`。无分配、无全局可变状态、无 OS 调用，不导出 C 符号（测试 wrapper 导出 `dong_select_emit`）。
