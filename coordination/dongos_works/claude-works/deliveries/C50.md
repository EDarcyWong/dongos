## 实现

`emit(module_name, item_name, callee_module, callee_item, incoming_count, argument_map, out, written)` 生成 `u64 f(a0..a{n-1}) { return callee(a[map[0]],...); }`。入参槽 `8*(i+1)`，结果专用槽 `8*(n+1)`，`frame = align_up(8*(n+1),16)`，mask 0。按任务书顺序实际调用：CR3 自身符号 + `:\n` → CR11 `prologue(frame,0)` → C37（kinds 全 0、offsets `8*(i+1)`）捕获 n 个入参 → C41 `emit(callee 名字, kinds 全 0, source_offsets[j]=8*(map[j]+1), return_kind 8, frame, low=结果槽, high 0)`（setup/call/cleanup/capture-return）→ C42 `emit(8, frame, 0, 结果槽, 0)` 读取结果并 `ret`。没有尾跳，不生成 callee 函数体，不输出 extern/global/section/bits。

预检顺序：written（非 NULL、8 对齐、端点）→ map 元素乘法（len ≤ MAX/8）→ 四个名字、map（8 对齐）、out 的端点/NULL → written 与 out 别名 → written、out 与每个完整名字和完整 map 的别名 → 四个名长 1..64 → incoming ≤ 6、map 长 ≤ 6 → 这之后才读 map，每项 < incoming → 自身两名字与 callee 两名字同时逐字节相等则 INVALID。全部 INVALID 先于 CAPACITY；名字与 map 之间允许重叠。最后才比较容量并一次性发布 out 与 `*written`。无分配、无全局可变状态、无 OS 调用，不导出 C 符号（测试 wrapper 导出 `dong_forward_emit`）。

## 与任务书的偏差（局部 scratch 大小）

任务书写"可 4096 最终 scratch，但必须留足 C41 段 1536、C37 段 1024"，按此分段合计 3020 字节。实际编译时 dongc 拒绝：3072 字节初始化缓冲报 `worst-case frame 6640 bytes exceeds 4096 bytes`，2048 报 4592，1792 及以下才能编译（带初始化的 `[N]u8` 约占 2N 帧空间；不初始化的数组会被检查器以"可能未初始化"拒绝）。所以本实现按"最多 6 个单字实参"的实证上界分段：符号 266、`:\n` 2、序言 64、C37 段 256（实际 ≤ 156）、C41 段 640（实际 ≤ 454）、C42 段 128（实际 50），合计 1356 ≤ 1536 字节缓冲。C37、C41 仍在各自完整的内部 scratch（1024/1536）中生成文本，这里只接收精确结果。实测最长输出 956 字节（四个 64 字节名字、6 入参、6 项 map），测试断言它与独立文本模型一致并 ≤ 1356。
