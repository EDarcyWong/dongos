## 实现

`lower(source, tokens, nodes, root, parameter_tokens, out, result)`，状态 OK/INVALID/CAPACITY/UNSUPPORTED = 0/1/2/3，`Result{instruction_count, slot_count, return_slot}`（24 字节）。校验顺序（全部通过前不写任何用户内存）：描述符（数量先于乘法，非 NULL、端点、8 对齐、out/Result 与所有完整输入及彼此不重叠，输入之间可重叠）→ root → token 流（范围、单调不交叠、EOF 只在最后）→ 每个 node.token 与参数 token 索引/种类/非空/互不相同 → **UNSUPPORTED**（kind 非 INTEGER/NAME/BINARY，或 BINARY operator 不在 `+ - * & | ^`；发生在安全索引检查之后、形状检查之前）→ 形状（`next=NONE`、`flags∈{0,1}`、各 kind 的 op/a/b/c、token 种类、BINARY.op 对应 token.kind 且拼写是该单字符、INTEGER 拼写 ≤256 且必须经 `bi.parse`、NAME 必须是参数）→ 带显式栈的遍历要求每个节点恰被访问一次（拒绝环、共享孩子、多父、不可达节点）→ 容量。降级为后序、NAME 不发指令、INTEGER → CONST 到新槽、BINARY 经显式映射到 ADD/SUB/IMUL/AND/OR/XOR，新槽从 p 开始；`slot_count = max(1, p+指令数)`。

局部数组合计约 1 KiB（values、slot_of、遍历 stack/state、2 个 u32 limb、32 个 u32 工作 limb，`tree_ok` 另有 visited/stack/state），没有 24 条 Instruction 的局部副本；所有检查完成并确认容量后才第一次写 `out`，然后写 `*result`。debug/release 都能在 dongc 4096 字节栈帧限制内编译。
