## 实现要点

- 三遍：结构（INVALID/DEPTH，只读）→ 种类（UNSUPPORTED/TYPE，只读，含短路右式）→ 求值（DIVZERO/SHIFT/WORKSPACE，只写 work）→ 发布（CAPACITY）。
- 树形状：要求与自举解析器一致的后序布局（节点在操作数之后、左子树整体在右子树之前），子树索引区间互不相交，所以共享节点和环都会 INVALID，且遍历线性，不需要访问标记写入 scratch。
- 中间值在 work 中按栈增长，各运算的预留见文档；所需工作区是可按树递推的精确值。

AST 由真正编译的董词法器 `dong_bootstrap_lex` 和表达式解析器 `dong_bootstrap_expression` 在原生驱动里生成，再调用 `dong_const_eval`。期望值由独立的 Python 求值器在 Python 侧树上计算（Python 整数，自写向零截断除法），树被渲染成 Dong 源码交给原生侧；Python 只额外镜像文档中的工作区预留规则，用来预测精确的 WORKSPACE 边界，不复制董的数值算法。

每次调用后 C 驱动立即检查：source 前后 guard 与内容、tokens/nodes 全内容不变（只读页例子放在 PAGE_READONLY 页上）、out/work/Value 前后 16 字节 guard、成功时 out 尾部未写、结果规范、布尔为 0/1；失败时整个 out 和 Value 不变；INVALID/DEPTH/UNSUPPORTED/TYPE 时 work 也不变。Python 在读取下一条之前先断言该条的 guard。
