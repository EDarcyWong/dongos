## 实现要点

- 严格按 setup → CR12 `emit(11,5,-target_offset,64,false)` → C27 `emit(11)` → cleanup（同一次 setup 的 `stack_bytes`）→ C40 capture 的顺序实际调用五个组件，没有重写任何一个。目标在 setup 之后才读进 R11，setup 用到的 RAX 和 rdi..r9 都不可能覆盖它。
- 本模块自己做完整的描述符、对齐、乘法、端点校验，以及 written/out 与两个完整输入的别名检查；再检查 frame、目标槽（8 对齐且 8..frame）、C34 的 kind/字数规则和源槽。返回布局交给 C40。所有 INVALID 都在局部 scratch 阶段得出，先于容量判断；任何失败都不发布任何子段。
- 局部 scratch 1280 字节，五段切片依次是 1024 / 64 / 16 / 32 / 64，写完后 `at` 最多 1200（证明见说明文档）。合法输入不会因内部容量被拒绝。

| bad-early-written | 容量不足时先写 `*written` 再返回 CAPACITY | 7 个标量 + PAIR 向量、容量 40，被 `guard/atomicity` 拒绝 |

## 限制

- 原生桩用显式 SysV C 桥调用；COFF 只组装加本机链接，不代表 Win64 ABI。ELF64 只组装，没有在 Linux 上执行。
- 被调用者是手写的测试函数，函数地址由测试桩在运行时写进帧槽；本组件按契约不检查运行时地址。
- 没有检查栈实参区的对齐填充字（C34 本身就不写它）。
- 只跑了本任务的定向测试；没有 OS/VM、全回归或 AI CLI；没有提交、推送或集成，等待独立复验。
