## 实现要点

- `build`：描述符 INVALID（used 非空/8对齐、`starts.len*8` 无溢出、三个区间指针/端点、对齐、两两不重叠，source 也不得与可写对象重叠）→ 第一遍计数 LF → `LF个数 >= starts.len` 返回 CAPACITY → 第二遍写 `[0]` 与每个 LF 后偏移 `i+1` → `*used`。无数据 INVALID。CR、NUL、0xA5、UTF-8 均为普通字节。
- `locate`：描述符检查（result 非空/对齐/16字节无回绕、starts 区间、二者不重叠）→ 数据检查（非空、`starts[0]==0`、严格递增、全部 `<= source_len`、`offset <= source_len`）→ 二分查找最后一个 `<= offset` 的起点（相等取该行）→ `offset-start == 2^64-1` 时列 +1 溢出返回 INVALID → 一次性写 `Position`。
- 非 OK 前不写任何输出；无分配、全局可变状态、OS 调用。


- 3 个 test：随机、边界、坏源码负控；debug/release 各编译一次，`elf64` 与 `win64` 都用 NASM 组装，本机格式与 C 观察器链接（`gcc -std=c11 -O2 -Wall -Wextra -Werror`）后原生运行。缺 NASM/GCC 时整类 skip（任务要求零 skip，这时应视为未达标）。
- Python 期望独立于实现：`split_starts` 用 `bytes.split(b'\n')` 的片段长度累加；`locate` 期望用 `bisect.bisect_right`；随机源码另用 `count/rfind` 直接模型交叉断言。
- 随机（种子 `0xC17C17`）：300 个长度 0–30 token 的源（a/Z/空格/LF/LFLF/CRLF/CR/NUL/0xA5/é/あ/😀），每源精确容量 build，部分额外容量、差一容量与 0 容量；对 0、EOF、每个行首和随机 offset 查找；越界 offset、`source_len` 大于末起点、重复起点、逆序、`starts[0]!=0` 等错误索引；10 万字节只读源及只读索引。断言 OK>1000、INVALID>500、CAPACITY>100。
- 边界：空源 `[0]`、空源 0 容量、尾 LF、连续 LF、CRLF、纯 CR、NUL、UTF-8 按字节计列、EOF（尾LF行为空行第1列）、相等 offset 取该行、`[0]`/`source_len=offset=2^64-1` 列溢出 INVALID、`2^64-2` 返回列 `2^64-1`、起点 `2^64-1`、空/非零首/非严格/超界索引；含真实只读输入（VirtualProtect/mprotect）。
- C 观察器逐调用检查：输入全文（含只读页）、输入前后 32 字节 guard、输出前后 16 字节 guard、失败时整个输出与 used/Position 不变、成功时输出尾部不变、结果对象两侧 guard。每个原生程序启动时先跑 13 个 build 与 8 个 locate 描述符预检（NULL、未对齐、重叠、`len*8` 溢出、长度越界、伪高地址），每项只含一个缺陷，要求 INVALID 且整个 arena 不变；伪高地址只出现在必被 span 检查拒绝的位置，且对齐、无别名，不分配巨大内存。
- 坏源码负控（私有临时根，debug/release 各编译、链接、原生运行；先用正式源码通过同一案例）：
  1. `bad-missing-tail-line`：`breaks` 忽略末字节 LF → `b'ab\n'` 返回 used=1，被 `'used'` 断言拒绝；
  2. `bad-equal-offset-prev-line`：二分用 `<` → `[0,3]`、offset 3 得 (1,4)，被 `'position'` 断言拒绝；
  3. `bad-overflow-writes-result`：列溢出时先写 result 再返回 INVALID → 被 `'guard/atomicity'` 断言拒绝。
  编译失败、崩溃、超时不会匹配这些正则，不算拒绝。
