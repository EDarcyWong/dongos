## 生产实现（沿用交接基线，未改动）

`bootstrap.nasm_guarded_integer_divide.emit(signed, remainder, zero_target, overflow_target, success_block, out, written)`：
- 依次实际调用 C31 `nasm_division_guard.emit(signed, zero, overflow, success)`、CR18 `nasm_block_emit.emit(0, success_block)`（定义成功标签一次）、CR19 `nasm_integer_divide.emit(signed, remainder)`。
- 顺序固定为门禁 → 成功标签 → 除法；不重写门禁或除法，不加额外的 jmp/ret/section。
- 校验：written/out 描述符和别名；三个标签都不能是 NONE，且两两不同。所有 INVALID 都先于 CAPACITY。
- 局部 scratch 上界：门禁 224（实际最多 197）、标签 32（最多 30）、除法 64（最多 60），合计 ≤ 287，最后一次性发布。

生产 `.dg` / `.md` 的 hash 和交接快照完全一致（`9c277fad…` / `85ddfac8…`）。审查之前我核对过三个依赖的源码：C31 门禁只用 RAX 当暂存，CR19 改写 RAX/RCX/RDX，两者都符合"成功时只有 RAX/RCX/RDX/flags 可变、异常路径不执行除法"的契约，所以没有理由重写。

## 本次对测试的补齐（只改 `tests/test_nasm_guarded_integer_divide.py`）

基线测试和 CR30（见 `reviews/2026-10-19-CR30-D21-independent.md`）是同一种写法，存在同样的两个缺口。这里按同样的标准主动补齐：

1. **完整保持集**：原来的 `_probe` 只检查 rdi/rsi/r8/r9/r10。新的安全桥：
   - 先 push 宿主的 rbx/rbp/r12–r15，再把状态指针压栈，并记录片段前的 RSP；
   - 给除 rsp 外**全部 15 个 GPR** 设不同的初值（RDI 是被除数、RSI 是除数）；
   - 执行片段；在成功落空、除零桩、溢出桩三个出口都先把 15 个寄存器全部 push，再拷进状态区，并记录路由标记和片段后的 RSP；
   - 最后恢复宿主 callee-saved，正常 ret；C 端检查状态区末尾的 guard。

   断言：成功时只有 RAX/RCX/RDX 可以变（RAX 等于独立 Python 模型的商或余数）；除零和溢出时只有 RAX 可以变（C31 的暂存），RCX/RDX 也必须保持；片段前后 RSP 相等。异常桩都是安全桩，不会执行除法，也不依赖 #DE。探针对象组装成 elf64 和 win64。
2. **语义负控的好侧改为 Dong 实际产出**：原来 `good=expected(...)` 是 Python 拼的文本。现在好侧直接取正式 debug/release 可执行文件对同一输入的实际输出（`run_both` 同时校验文本），先原生执行并检查路由、数值和完整保持集，然后再执行坏体。
3. **新增保持寄存器数值负控 bad-clobber-rbx**：真实坏 Dong 在发布的文本末尾追加 `mov rbx, 61453`。在 signed 7/2 的商上，好侧先通过；坏体正常编译、链接，执行后走成功路径正常返回，商本身也是对的（3），但捕获到的 rbx 被改了，由保持断言里的 `'rbx'` 拒绝。没有靠崩溃。
