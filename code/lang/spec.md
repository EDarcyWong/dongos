# Dong v0.1 语言规格（L0 第一版）

- 日期：2026-10-16
- 状态：完整规格仍待实现和 ABI 实测；已有整数、部分控制流、聚合布局、内存访问、切片、模块、透明别名、全局存储与聚合/对象地址常量，并已将多个探针链接进 P1 内核实启，详见 `lang/README.md`。这不表示完整 L1 或标准库已存在。
- 目标：让 Python 编写的 `dongc` v1 能生成可读的 NASM 汇编，支持 DongOS P2–P4 所需的系统模块。NASM 与链接器仍由构建系统调用。
- 平台：x86-64、小端、64 位指针，ELF64 内核/程序与 Win64 COFF 引导器模块；无宿主操作系统依赖。

文中的“必须”是实现和测试要求。这里的 v0.1 是语言版本，v1/v2/v3 是计划中的编译器版本。当前实现状态见 [README.md](README.md)。

## 1. 范围与设计决策

v1 支持整数、布尔、固定数组、结构体、裸指针、切片、函数指针、有限的带数据枚举、可选值、错误返回、模块、方法、`defer` 和受限内联汇编。没有 GC、异常展开、隐式分配、线程运行时或自动资源析构。边界检查和诊断可能调用显式的 panic 接口；“无运行时”不意味着检查完全没有指令或辅助函数。

下列决定收敛了 [PLAN.md](../PLAN.md) 第 8、9 节的范围；修改计划时应同步这些决定：

| 计划中的表述 | v0.1 决定 |
| --- | --- |
| 与 System V AMD64 完全一致 | v1 实现下文规定的整数/指针与特定双字值子集；不宣称完整 C ABI。浮点、可变参数、任意聚合值跨 ABI 暂不支持。 |
| 引导器也用 Dong | 所有函数默认 SysV；UEFI 函数和回调显式写 `extern "win64"`。两种约定混用必须生成桥接所需的保存/栈操作。 |
| 结构体偏移由工具表生成；另有“从 Dong 导出”描述 | Dong 类型声明与编译器布局器是唯一来源。后续 `gen_offsets.py` 读取布局清单，只负责输出 NASM 常量，不能维护第二张手写偏移表。 |
| 安全语言、`unsafe` | v1 提供边界、初始化、类型和可见性检查，但没有所有权/借用/生命周期检查；不能承诺内存安全或无数据竞争。`unsafe` 是明确的审查边界。 |
| 任意内联汇编 | v1 只支持第 12 节列出的无操作数指令。寄存器输入输出、特殊入口和 SIMD 用外部汇编包装器。 |
| 类型推导、方法、容器 | 仅局部变量与字面量有推导；方法是普通函数的语法糖。泛型和通用容器留到后续，避免阻塞内核。 |
| `defer` 在函数退出时执行 | v0.1 采用词法块退出执行，含 `return`、`try`、`break`、`continue`。函数顶层的用法与计划示例相同。 |

后续特性：浮点和向量类型、泛型、接口/动态分发、闭包、递归数据枚举、借用检查、异常、异步、宏、运算符重载、可变参数、任意内联汇编、完整 C 聚合 ABI、TLS 语法、包管理、格式化插值、优化和源码调试信息。v1 遇到这些写法必须诊断，不能悄悄按近似语义编译。

## 2. 源文件、词法和基本语法

源文件使用无 BOM 或带 UTF-8 BOM 的 UTF-8，扩展名 `.dg`。换行可为 LF 或 CRLF；诊断中的行列从 1 开始，列按 Unicode 码点计数。标识符区分大小写，使用 Unicode XID_Start/XID_Continue 与 `_`，允许中文；不做隐式 Unicode 规范化。关键字固定英文，不能作为标识符。

`//` 到行尾是注释，`/* ... */` 是不嵌套块注释。字符串不能含未转义换行。整数允许十进制、`0x` 十六进制、`0b` 二进制，数字之间可用 `_`。无浮点或字符字面量；ASCII 码可写整数。转义支持 `\n`、`\r`、`\t`、`\0`、`\\`、`\"`、`\xNN`；字符串最终是 UTF-8 字节序列。

简单声明和语句以 `;` 结尾；`{ ... }`、函数/类型声明和块形式控制流不加分号。计划示例省略了分号，v0.1 正式语法要求分号，以简化分析和诊断。

```text
module mm.page;
import core.mem;
import sync.spin as spin;

pub const PAGE_SIZE: usize = 4096;
struct Page { next: *Page, flags: u64 }
type PhysAddr = u64;

fn round_down(addr: PhysAddr) PhysAddr {
    let mask: u64 = PAGE_SIZE - 1;
    return addr & ~mask;
}
```

类型声明的字段/变体以逗号分隔，允许末尾逗号。类型别名透明，不形成独立的强类型。关键字至少保留：`module import as pub const let var type struct enum fn extern unsafe packed align export if else while loop for in match break continue return defer try error orelse true false null void noreturn`；`asm` 为受限指令块关键字。

## 3. 类型与值

| 类型 | 大小/对齐 | 含义 |
| --- | --- | --- |
| `u8 u16 u32 u64` | 1/2/4/8 字节，分别同尺寸对齐 | 无符号整数 |
| `i8 i16 i32 i64` | 同上 | 二进制补码整数 |
| `usize isize` | 8/8 | 本目标中等价于 `u64` / `i64` |
| `bool` | 1/1 | 只能是 `false` / `true`，存储表示 0 / 1 |
| `*T` / `*const T` | 8/8 | 可写/只读的裸指针，允许空值 |
| `[N]T` | `N * sizeof(T)` / `alignof(T)` | 固定数组，`N` 是正的编译期整数 |
| `[]T` / `[]const T` | 16/8 | 切片，依次为数据指针、`usize` 长度 |
| 函数指针类型 | 8/8 | 包含类型层面的 ABI 与 unsafe 属性，表示非空代码指针 |
| `void` | 无可存储值 | 函数无返回值 |
| `noreturn` | 无可存储值 | 函数不会正常返回 |

结构体、枚举、`?T` 和 `!T` 见后文。v1 不允许零长数组、空结构体、直接按值递归的类型、`*void`、`[]void` 或存储 `void`/`noreturn`。无类型内存用 `*u8`。可以通过指针构造递归结构体。

未定类型的整数常量先按任意精度求值，再由上下文确定整数类型；无上下文时默认 `i64`，超范围报错。常量溢出所有构建模式均报错。`let x = null;` 和空数组字面量不能推导类型。不同宽度/符号整数之间没有隐式转换，比较也要求同类型；常量可适配已知类型。`usize`/`u64` 是此规则的别名例外。

未定整数表达式中的移位和按位补码在上下文确定宽度后求值；普通常量算术中间量保留任意精度，最终结果须适配目标类型。例如 `u8` 上下文的 `256 - 1` 是 255，`(128 << 1) + 1` 是 1，`(1 << 8) - 256` 因移位量不小于 8 而报错。

`let` 禁止重新赋值；`var` 允许赋值。不可变绑定的结构体/数组字段同样不可写，但 `let p: *T` 仍可通过指针修改它指向的对象。局部绑定从声明到所在块末尾可见，同一块重复声明报错，内层块允许显式同名遮蔽；初始化器查找新绑定之前的作用域。`*T`、`[]T` 可隐式转成相应只读类型，反向转换只允许在 `unsafe` 中。

`null` 仅适配裸指针或可选类型；不可选函数指针不接受它。没有整数/指针到 `bool` 的隐式转换。字符串字面量的类型是 `[]const u8`，指向永久只读存储，长度按 UTF-8 字节计数，不含 NUL；需要 UTF-16 或 NUL 结尾的数据时显式声明数组，v1 不做自动编码转换。

## 4. 声明、初始化与表达式

```text
const COUNT: usize = 4;
var boot_count: u64 = 0;                 // 全局初始化只能是常量表达式

fn example() u64 {
    let limit = 10;
    var total: u64 = 0;
    var work: [4]u8 = [0; 4];
    let pair = [1, 2];                  // 推导为 [2]i64
    var page: Page = Page { next: null, flags: 0 };
    var result: u64;                     // 在每条使用路径上必须先整体赋值
    result = page.flags;
    return result;
}
```

数组字面量为 `[a, b, c]` 或 `[value; N]`。结构体字面量为 `Type { field: value, ... }`，字段必须各出现一次，无默认字段值。局部未初始化变量仅允许 `var name: T;`；在读取、取地址、创建切片、作为接收者或作为参数前必须整体初始化。v1 不跟踪逐字段初始化，给未初始化结构体单个字段赋值报错。全局 `var` 必须写初始化器；零数组写 `[0; N]`。无隐式 BSS 未初始化对象语义。

确定初始化分析按控制流求交集；循环可能执行零次，不能仅靠循环体中的赋值证明初始化。未初始化变量取地址传给函数“代为填充”不被接受，应先显式置零。不可达代码可警告；`noreturn` 调用后无后继路径。

赋值 `= += -= *= /= %= &= |= ^= <<= >>=` 是语句，不产生值；复合赋值的左侧地址只求值一次。除赋值和控制流外，独立表达式语句仅允许函数调用或 `try` 包装的调用。二元操作从左到右求值，调用的接收者、参数和字面量元素也从左到右求值；每个子表达式只求值一次。

优先级从高到低如下；相同级别默认左结合：

| 级别 | 操作 |
| --- | --- |
| 后缀 | 调用 `f(...)`、字段 `.x`、索引 `[i]`、切片 `[lo..hi]` |
| 前缀（右结合） | `!`（逻辑非）、`~`、`-`、`&`（取地址）、`*`（解引用）、`try` |
| 转换 | `expr as T` |
| 乘法 | `* / %` |
| 加法 | `+ -` |
| 位移 | `<< >>` |
| 按位与/异或/或，各独立一级 | `&`、`^`、`|` |
| 比较 | `== != < <= > >=`，禁止链式比较 |
| 逻辑与/或，各独立一级 | `&&`、`||`，短路 |
| 可选回退（右结合） | `orelse`，短路 |

`unsafe { ... }` 是语句块，不是表达式；`if`/`match` 也不产生值。无隐式尾表达式返回。`&place` 的结果是裸指针，绑定的可写性决定是否带 `const`；取地址不构成对齐、有效期或非空保证。`*p` 读写、指针索引和指针加减需要 `unsafe`。

指针加减整数按元素大小缩放，只支持 `p + n`、`p - n`，`n: usize`；运算结果必须仍在原分配对象内或恰好末尾，整数地址计算需要先转 `usize`。v1 不支持两个指针相减。指针只支持同类型的 `==` / `!=`，不支持大小比较。

整数 `as` 转换截取低位；拓宽按源类型符号扩展或零扩展。`bool` 只能显式转成整数；整数转 `bool` 用 `x != 0`。整数与指针之间的转换只接受 `usize` 并要求 `unsafe`；指针重解释和去掉 `const` 也要求 `unsafe`，不自动保证目标类型的布局或对齐。

## 5. 控制流、数组和切片

```text
if ready && count != 0 { use_value(count); } else { idle(); }
while i < n { i += 1; }
loop { if done { break; } }
for i in 0..n { consume(i); }             // usize，左闭右开，边界仅求值一次
for byte in data { consume_byte(byte); }  // 数组/切片，按值遍历，无隐式引用
```

条件必须是 `bool`；范围边界必须同为 `usize`，下界超过上界时循环执行零次。`for` 的范围或数组/切片表达式只求值一次，数组/切片遍历不复制整个底层存储；循环变量不可变。v1 无循环标签，`break`/`continue` 作用于最近的循环；不允许 `break value`。`return;` 用于 `void` 或第 9 节的 `!void`；所有能正常退出的非 `void` 函数必须显式返回。控制流条件中若出现结构体字面量，必须用圆括号包住整个字面量，避免与紧随的块混淆。

数组/切片索引是 `usize`，读取/赋值前检查 `i < len`。`a[lo..hi]` 创建视图，检查 `lo <= hi <= len`，省略下/上界分别取 0/长度。由数组创建切片时，可写性继承源 place：可写的 `var` 数组或可写字段产生 `[]T`，不可变的 `let` 数组或只读字段只能产生 `[]const T`。已有切片取子切片时保持其元素可写性；`let s: []T` 仅禁止重新绑定描述符，仍允许 `s[i] = value`，与 `let p: *T` 一致。切片不因描述符的不可变绑定而自动变为 `[]const T`。

普通切片还要求元素地址满足 `alignof(T)`。v1 必须拒绝从无法证明元素自然对齐的数组 place 创建切片，包括可能非对齐的 packed 数组字段；`unsafe` 块本身不关闭这条诊断。需要处理这类字段时，可以先按值复制到普通的对齐数组，再取切片；或在调用者确实验证了地址对齐后显式使用 `slice_from_raw_parts`。不能仅凭 packed 字段的数组类型就推断它的存储已对齐。

`a.len` 和 `s.len` 是只读 `usize`，`s.ptr` 是相应裸指针。空切片允许空数据指针；非空切片必须指向至少 `len` 个连续、初始化且对齐的 `T`。

切片不拥有存储，不会复制元素。编译器没有生命周期分析；存储失效后的切片即使索引未越界也无效。数组借用成切片不会延长数组生存期。创建裸指针切片用 `slice_from_raw_parts(ptr, len)`，是 `unsafe` 内建，调用者保证上述不变量和乘法/地址范围不溢出。来自用户地址的切片不能绕过 `copy_from_user` 等内核校验。

## 6. 结构体与内存布局

```text
struct BootInfo { revision: u32, memory_map: *const u8, map_len: usize }
packed struct Descriptor { limit: u16, base: u64 }
align(4096) struct PageTable { entries: [512]u64 }
```

普通结构体按声明顺序布局。每个字段偏移向上取整到字段对齐，整体对齐为各字段对齐最大值，整体大小补齐至整体对齐。数组元素连续排列，步长为元素大小。字段顺序永不优化重排。

`packed struct` 中字段无填充、整体对齐 1。字段直接读写必须生成允许非对齐的访问；不能将其当作已对齐的原子或 MMIO 对象。`&packed_value.field` 可以形成保留可写性的裸指针，但不建立自然对齐保证；通过该指针进行普通解引用、构造切片、原子或 volatile 访问时，调用者仍须满足相应对齐契约。需要非对齐整数访问时使用 `read_unaligned` / `write_unaligned`；它们不把非对齐存储变成可用的原子或 MMIO 对象。第 5 节的直接切片构造规则仍须静态检查。

`align(N)` 提高类型整体对齐，`N` 必须是 1–4096 的 2 的幂，不得降低自然对齐；尾部补齐至新对齐。v1 不允许 `packed` 与 `align` 同时出现，也无单字段对齐属性。自动存储和全局存储都必须满足最终类型对齐，栈上超出 16 字节的对齐由函数序言处理，并计入第 10 节的实际栈帧限制。

局部结构体/数组可以初始化、赋值和复制，复制含逻辑值及未规定的填充字节，不保证填充值。聚合值不能用 `==` 比较。磁盘、网络、IPC 等外部数据必须逐字段编码/校验，不能依赖填充字节；`packed` 也不提供字节序转换或协议验证。

以下内建在编译期求值：`sizeof(T)`、`alignof(T)`、`offsetof(T, field)`，结果为 `usize`。`offsetof` 只接受直接结构体字段。常量求值支持字面量、已声明常量、整数/布尔运算、这些布局内建和成员为常量的数组/结构体构造，不执行任意用户函数。函数地址和全局对象地址可用作带链接重定位的常量；地址不能在编译期转整数、比较大小或参与整数计算。布局计算溢出、循环依赖或不满足类型限制必须报错。

布局清单的目标字段至少包含：目标标识、类型全名、大小、对齐、各字段名称/偏移/类型。导出只读布局结果不能改动源类型。汇编与 Dong 互用的结构必须有布局测试；C 名称相似不代表布局自动相同。

## 7. 函数、方法与模块

```text
module mm.page;

pub fn inspect(page: *const Page) u64 {
    unsafe { return (*page).flags; }
}

unsafe fn (page: *Page) clear() void {
    unsafe { (*page).flags = 0; }
}

type Handler = unsafe extern "sysv64" fn(vector: u64) void;
```

函数写成 `fn name(params...) ReturnType { ... }`；返回类型不可省略。v1 无重载、默认参数、可变参数或嵌套函数。模块中的声明先收集再检查函数体，允许相互递归。`noreturn` 函数不得包含任何形式的 `return` 或可达的正常函数结尾，每条路径必须不终止或调用另一个 `noreturn` 函数。方法 `fn (self: *T) method(...) R` 只允许定义在 `T` 的声明模块，接收者须为 `*T` 或 `*const T`；`p.method(x)` 等价于 `method(p, x)`，不自动取地址、解引用或转换可写性。

函数声明中的 `unsafe` 要求调用点位于 `unsafe` 块内；函数体仍必须显式写 `unsafe` 块才能执行不安全操作。它是调用者契约，不是跳过所有检查的开关。函数名可在上下文中转换成精确匹配的函数指针；ABI、参数、返回值、`unsafe` 属性均属于类型。调用函数指针本身也是 `unsafe`，必须保证代码地址有效且目标签名一致。

每个文件以一个 `module a.b;` 开头。一次编译中一个模块对应一个文件，文件由模块路径相对指定源码根解析为 `a/b.dg`；不从当前目录或网络隐式搜索。多个源码根出现同名模块报错，导入循环在 v1 报错。

`import a.b;` 绑定最后一个名称 `b`，`import a.b as c;` 绑定 `c`，用 `c.name` 访问。模块顶层默认私有，`pub` 可用于函数、类型、错误声明和常量/全局变量；结构体字段默认私有，写 `pub field: T` 可跨模块访问。枚举变体的可见性与枚举本身相同。私有类型不能暴露在公开签名中。无通配导入、再导出或隐式预导入；内建类型/内建操作除外。

普通符号名确定为 `__dg_m<完整模块名UTF8十六进制>_f<函数或全局名称UTF8十六进制>`；模块名包含分隔点，例如 `mm.page` 整体编码。方法使用 `__dg_m<模块编码>_t<所属类型名称编码>_f<方法名称编码>`。十六进制一律小写，这些编码与分隔标记使普通函数/全局/方法无歧义，且不依赖宿主机区域设置。`export("symbol") fn ...` 指定 ASCII 外部链接名，允许字母、数字、下划线且不能以数字开头；重复导出报错。`pub` 本身不固定外部链接名。

## 8. 可选值、枚举与匹配

v1 的 `?T` 限于整数、`bool`、裸指针或函数指针载荷；不嵌套 `?`/`!`。表示为 `{ tag: u64, value_slot: u64 }`，对齐 8、大小 16，`tag=0` 是空、`tag=1` 是有值。小整数占槽低位，未用高位必须置零；有符号数恢复时按其类型符号解释。空值槽必须置零。这里不使用空指针优化。

有上下文时 `T` 自动提升为 `?T`，`null` 构造空值。`maybe orelse fallback` 解出 `T`，只有空值时求值右侧；右侧可以是 `return expr`、`break` 或 `continue`，也可为 `T` 表达式。没有隐式空值解包。

```text
enum Event { Timer, Key(u8), Shutdown }

fn key_code(event: Event) u8 {
    match event {
        Event.Timer => { return 0; },
        Event.Key(code) => { return code; },
        Event.Shutdown => { return 0; },
    }
}
```

枚举变体按声明顺序从 0 编号。无载荷枚举仅存 `u64` 标签；只要有任一载荷，整个类型就使用 16 字节 `{ tag: u64, value_slot: u64 }`。每个变体最多有一个载荷，类型限制与 `?T` 相同；不支持自定标签值、嵌套载荷或匿名联合。构造分别写 `Event.Timer`、`Event.Key(value)`。无载荷变体的值槽为零。

`match` v1 只支持枚举、`bool`、可选值和第 9 节的错误结果。可选模式为 `null` 和 `some(name)`；布尔模式为 `true` / `false`；`_` 为兜底且只能最后出现。每种可能必须覆盖，重复/不可达分支报错。变体绑定不可变且仅在分支中有效。无守卫、范围模式或自动贯穿；匹配期间被匹配值求值一次并保留副本。

外部内存里的任意标签字节不是合法的 Dong 枚举。将其解释为枚举前必须验证，v1 不提供直接整数到枚举转换。无效标签/布尔表示违反 `unsafe` 契约；安全逻辑不能依赖这些非法值的行为。

## 9. 错误返回与 defer

```text
error OutOfMemory = 1;
error InvalidAddress = 2;

fn allocate_one() !*Page {
    lock.acquire();
    defer lock.release();
    let page = free_list.pop() orelse return error.OutOfMemory;
    unsafe { page.clear(); }
    return page;
}

fn initialize() !void {
    let page = try allocate_one();
    consume(page);
    return;
}
```

示例中的 `lock`、`free_list` 和函数是接口示意，不是现存标准库。错误声明是模块顶层常量，编号必须在 `1..=0xffff_ffff` 范围内，同一最终程序中编号唯一；0 保留为成功，跨模块重复编号在模块图检查/链接前报错。错误可写 `pub error OutOfMemory = 1;` 供其他模块使用；导入模块别名为 `err` 时，通过 `error.err.OutOfMemory` 引用。同一声明经多个路径导入只计一次。v1 不自动分配错误码，也没有错误字符串运行时注册表。

`!T` 的载荷限制与 `?T` 相同，另允许 `!void`。表示为 16 字节 `{ code: u64, value_slot: u64 }`，对齐 8；成功时 `code=0`，失败时是声明的错误编号。`!void` 的成功值槽为零，所有失败值槽均为零。

在返回 `!T` 的函数中，`return value;` 包装成功，`return error.Name;` 返回失败；返回 `!void` 时 `return;` 包装成功。同类型错误结果也可以直接 `return other_call();` 转发。`try expr` 要求 `expr: !T` 且当前函数也返回错误类型；成功时产生 `T`，失败时运行离开作用域所需的 `defer` 后原样传播错误码。`try` 不能出现在全局初始化中。直接把 `!T` 调用结果作为独立语句丢弃报 `E0301`。

需要就地恢复时用 `match result`：成功模式是 `ok(value)`，失败模式是 `err(code)`，其中 `code: u64` 是原错误编号；`!void` 的成功模式为 `ok`。两个模式必须穷尽，失败模式覆盖所有错误编号，可在块内继续比较 code。模式中的 `ok` / `err` 仅在此上下文有特殊含义。没有隐式 `try`、异常捕获或栈展开。

`defer` 后接单条调用语句或 `{ ... }` 块。在执行到该语句时注册，离开所属词法块时按注册逆序执行。未执行到的注册不执行；循环体每次迭代独立。被引用变量在清理实际执行时读取，因此可反映后续赋值；允许引用的局部变量必须在注册点已经初始化且在清理前仍有定义。

返回表达式先求值并保存，再执行清理，清理不能改变已保存的返回值。`return`/`try` 离开所有当前作用域，`break`/`continue` 仅离开到相应循环边界；正常块末尾也执行清理。`defer` 体内禁止 `return`、`try`、`break`、`continue` 和嵌套 `defer`。panic、CPU 异常、断电、进程强制终止不运行清理。

## 10. 调用约定与汇编边界

所有 Dong 普通函数使用此节规定的 SysV 子集，与内核/用户程序一致。每个函数建立可回溯的 `rbp` 帧，禁止使用 red zone，不生成浮点、SSE、AVX 或隐式 SIMD 拷贝。此限制也用于引导器编译；SIMD 由显式外部汇编实现。下文 Win64 桥接保存/恢复 XMM 状态的包装器属于显式汇编边界，不属于普通 Dong 代码。

### 10.1 v1 可按值传递的类型

标量为整数、`bool`、裸指针、函数指针和无载荷枚举。切片、可选值、错误结果、带载荷枚举为特殊的 16 字节双字值。v1 普通函数支持这些类型按值传递/返回；双字值按内存顺序拆为两个 INTEGER 类八字节单元。

任意结构体和数组不能按值作为函数参数/返回值，即使恰好 8 或 16 字节也一样；使用 `*const T` 输入、`*T` 输出。这是 v1 的显式限制，不会偷偷改成另一种 ABI。局部复制不受影响。不能在函数边界对不支持的类型简单强制转换成双字值。

### 10.2 SysV AMD64 整数子集

- 整数/指针参数依次使用 `rdi rsi rdx rcx r8 r9`；小于 64 位只依赖相应低位，调用者先按类型扩展到 64 位，接收外部返回/参数时不能假定高位已扩展。
- 一个双字值需要两个连续参数寄存器；不足两个时整个值放栈，不能一半寄存器一半栈。该次失败分配不消耗剩余寄存器，后续标量仍可使用它。
- 栈参数按源码参数顺序确定位置，第一项在被调用者入口的 `[rsp+8]`；每项占其大小向上取整到 8 的空间。布局必须预先计算，调用前用于 16 字节对齐的额外填充放在参数区域尾部，不能插在第一项前。
- 标量返回值使用 `rax` 的对应低位；双字值使用 `rax` / `rdx`。`void` 无返回值。
- 被调用者保留 `rbx rbp r12 r13 r14 r15 rsp`；其余通用寄存器调用者保存。`call` 前 `rsp` 为 16 字节对齐，刚进入函数时 `rsp % 16 == 8`。
- 方向标志在普通函数入口和返回时必须清零。普通函数没有中断栈帧、`iretq`、`syscall` 或 `sysret` 语义。

`extern "sysv64" fn name(...) R;` 声明外部符号。v1 extern 只接受标量参数/返回值和 `void`/`noreturn` 返回值，不接受双字值或聚合值；外部切片、错误结果等接口用显式指针/长度/状态参数表示。链接名默认是声明名称，可写 `extern "sysv64" ("external_name") fn local_name(...) R;` 指定实际符号。外部声明默认按 `unsafe` 函数处理，调用要求 `unsafe`。

### 10.3 Microsoft x64 / UEFI

```text
extern "win64" fn firmware_call(handle: *u8, message: *const u16) u64;
export("efi_callback") extern "win64" fn callback(handle: *u8) u64 {
    return 0;
}
type OutputString = unsafe extern "win64" fn(self: *u8, text: *const u16) u64;
```

带函数体的 `extern "win64" fn` 定义一个使用该约定的回调或入口；其函数体仍可调用默认 SysV 函数。无函数体时是外部声明。省略 `extern` 的定义不会随输出目标自动切换 ABI。

- v1 Win64 签名仅支持标量参数/返回值；不支持浮点、可变参数和聚合参数/返回值。整数和地址返回在 `rax`。
- 前四个参数依次使用 `rcx rdx r8 r9`，调用者始终分配 32 字节 shadow space，第五参数在被调用者入口 `[rsp+40]`，后续每项 8 字节。
- `call` 前栈同样 16 字节对齐；调用者在返回后回收 shadow space 和栈参数。
- Win64 被调用者保留 `rbx rbp rdi rsi r12–r15 rsp` 和 `xmm6–xmm15`。Dong 不生成 SIMD，但 Win64 定义如果调用 SysV 代码，桥接必须保护这些 Win64 非易失 XMM 寄存器，或拒绝无法证明安全的调用；不得用“本函数不用 SIMD”忽略外部 SysV 函数可破坏它们。
- 实现优先用外部汇编桥接封装 Win64→SysV 边界；v1 若尚未实现完整保存，遇到这样的函数体调用必须给出“不支持 ABI 桥接”的编译错误。这项不能在 UEFI 回调验收中略过。

v1 不生成 PE/COFF SEH 展开信息，不支持异常穿过 Dong 栈；固件回调不得要求异常展开。v1 不生成栈探测，拒绝最坏情况下栈帧超过 4096 字节的函数；核算必须包括局部对象、临时值、保存的寄存器、动态对齐的最大填充以及最大出参/shadow space，而不只是源码变量大小。递归/调用链总栈量仍由系统代码控制。页表等大对象应使用已分配的页或全局对象。

系统调用寄存器约定独立于函数 ABI。`syscall` 包装器、系统调用入口、中断入口、上下文切换和每核 `gs`/用户 `fs` 操作由手写汇编提供，不能通过普通 `extern` 函数体冒充入口。

## 11. 检查、unsafe 与硬件内存

所有构建模式都检查切片/数组边界、除数为零和位移量小于操作数位宽；有符号除法 `MIN / -1` 也 panic。移位右侧必须为 `usize`，有符号右移作算术移位，左移截去高位。

调试模式的整数 `+ - *` 和一元负号溢出触发 panic；发布模式明确定义为按位宽模运算，不允许优化器把溢出当成“不可能”。`wrapping_add(a,b)`、`wrapping_sub(a,b)`、`wrapping_mul(a,b)` 在两种模式均按模运算。整数除法向零截断，余数与被除数同号。常量非法运算总是编译错误。

只有以下操作需要 `unsafe`；普通检查不会因此自动关闭：

- 裸指针读写、索引、算术，整数/指针重解释与去掉只读限定。
- 从裸指针创建切片，调用外部/unsafe 函数或任意函数指针。
- 内联汇编、volatile/原子/非对齐内建。

调用者负责有效地址范围、映射权限、初始化、类型表示、对齐、有效期、别名和并发同步。编译器 v1 不做自动空指针、指针有效性或数据竞争检测。普通指针读写无 volatile 或原子含义；用户地址、MMIO、DMA 缓冲区也没有天然特权。

v1 提供下列类型推导内建，指针目标仅支持 `u8/u16/u32/u64` 或相应有符号整数，返回/写入类型必须一致：

| 内建 | 语义 |
| --- | --- |
| `volatile_load(p)` / `volatile_store(p, value)` | 恰好一次指定宽度访问，不删除、合并或相对其他 volatile 访问重排；要求自然对齐。不是线程同步，也不自带设备所需 CPU 屏障。 |
| `read_unaligned(p)` / `write_unaligned(p, value)` | 普通非对齐整数读写，可分解，不保证一次总线访问或原子性，不用于 MMIO。 |
| `atomic_load(p)` / `atomic_store(p, value)` | 仅 `u32/u64`、自然对齐、普通可缓存内存；v1 固定顺序一致性。 |
| `atomic_compare_exchange(p, expected, desired)` | 同上；返回旧值，旧值等于 expected 表示交换成功，强比较无伪失败。 |
| `atomic_fetch_add(p, delta)` | 同上；返回旧值，按模加法。 |
| `compiler_fence()` | 禁止编译器把内存操作移过此点；不生成 CPU 屏障。 |

这些内建在 v1 都要求显式 `unsafe` 块。原子访问必须在同一对象上持续一致使用，不能与无同步的普通访问混用；设备内存不允许使用这些原子内建。CPU 屏障由下一节的显式指令或外部包装器实现，内存类型、缓存一致性和设备协议仍由系统代码管理。

## 12. 汇编与运行时接口

`unsafe { asm { cli } }` 是 v1 内联汇编的完整形态；每块恰好一条无操作数指令。白名单为 `cli sti hlt pause int3 lfence sfence mfence`。不允许文本插值、寄存器/内存操作数、跳转、标签、`ret`、栈指令或 NASM 指令。每个 asm 块都是不可删除的副作用与完整编译器内存屏障，不能复用穿过它的条件码。

白名单不检查当前特权级或机器状态；错误使用仍会触发硬件异常。端口 I/O、CR/MSR、CPUID、`xsave`、CET、用户拷贝、SIMD 等采用显式类型的外部汇编函数。这样 v1 无须实现寄存器约束求解器，也不会以任意文本破坏函数栈帧。

边界/算术检查失败调用构建目标提供的：

```text
extern "sysv64" fn __dong_panic(kind: u32, line: u32,
                               file: *const u8, file_len: usize) noreturn;
```

`kind` 固定为：1 边界、2 算术溢出、3 除零、4 位移量、5 有符号除法溢出。`file` 指向永久只读 UTF-8 数据，不含 NUL，路径应映射为构建源码根下的相对路径以便重现。该接口不能分配内存、返回或抛异常；UEFI、内核、用户程序分别提供适当实现。panic 不执行 `defer`。编译器不得在未声明的情况下依赖 libc 的 `memcpy`/`memset`/栈探测/异常库等符号；需要的辅助符号必须列入编译产物清单。

## 13. 标准库的 v1 最小范围

标准库与编译器分开验收；没有自动导入，也没有默认堆。硬件访问依赖具体平台模块，不能放进可移植 API 后悄悄使用特权指令。

| 模块 | v1 范围 | 留到后续 |
| --- | --- | --- |
| `core.mem` | 原始字节复制/移动/清零/比较；指针与长度明确，复制说明重叠契约；布局内建的薄封装 | 通用分配器、类型化容器 |
| `core.slice` | 字节切片的边界检查辅助、比较、查找 | 泛型迭代器、所有权容器 |
| `core.int` | 固定宽度对齐计算、checked/wrapping 辅助；失败用状态或 `!usize` | 大整数、浮点数学 |
| `core.fmt` | 向调用者提供的缓冲区/输出回调写十进制、十六进制和 UTF-8 字节；容量不足显式返回错误 | 字符串插值、可变参数、隐式分配 |
| `arch.x86_64` | 受审查的外部汇编包装器声明：端口 I/O、CPU 寄存器、屏障等，区分特权要求 | 自动 CPU 特性调度、通用 SIMD API |
| `sync.spin` | 基于原子内建和 pause 的自旋锁；清楚记录中断/抢占前提 | 无锁容器、通用调度运行时 |

UEFI 协议结构、内核分配器/日志/用户拷贝和用户态 syscall/IPC 是对应目标的项目模块，按 P1–P4 逐步实现；控件库、字符串容器、文件系统客户端不属于 L1 前置标准库。错误码通过项目共享模块分配，不能让不同库碰巧复用编号。

## 14. 编译接口、诊断与 L1 验收

完整编译器拟提供的命令接口如下。当前标量子集只实现其中一部分，实际支持范围与命令见 `lang/README.md`；下列完整示例不能作为已通过编译的程序：

```text
dongc --target x86_64-dongos-elf --mode debug --root kernel \
      --emit-asm build/kernel.asm --emit-layout build/layout.json kernel/main.dg
dongc --target x86_64-uefi-coff --mode debug --root boot \
      --emit-asm build/boot.asm boot/main.dg
dongc --check --root lang/tests lang/tests/example.dg
```

入口文件决定模块依赖图；所有模块按确定顺序输出到指定汇编文件。汇编使用 NASM Intel 语法及 `default rel`，本地代码/静态数据寻址使用 RIP 相对形式；函数指针和全局初始化中的地址使用明确的链接重定位，构建目标负责最终镜像的重定位加载。禁止因为内核位于高半区而把地址静默截成 32 位。布局清单必须声明模式/目标/规格版本。`--check` 只做词法、语法、名称、类型、控制流和 ABI 支持检查，不调用 NASM；成功返回 0，用户源码错误返回 1，工具内部/IO 错误返回 2。失败时不得留下貌似成功的部分 `.asm`/布局文件，应写临时文件后原子替换。

诊断格式为 `path:line:column: error[code]: message`，附源码片段及相关声明位置。中文标识符必须原样显示；消息可先用英文，但代码稳定。至少区分：

| 代码 | 诊断 |
| --- | --- |
| `E0001` | 非法 UTF-8、字面量、字符或未终止注释/字符串 |
| `E0101` | 语法错误，给出期望 token |
| `E0201` | 名称未定义/重复定义/不可见 |
| `E0202` | 模块缺失、冲突或循环依赖 |
| `E0301` | 类型不匹配或不能推导 |
| `E0302` | 非法布局、常量溢出或循环类型 |
| `E0401` | 可能使用未初始化变量 |
| `E0402` | 不可变赋值或非 void 路径缺少返回 |
| `E0403` | match 非穷尽、重复或非法分支 |
| `E0501` | 需要 unsafe / 违反 defer、try 上下文 |
| `E0601` | 不支持的类型/ABI/特性或超出帧大小限制 |
| `E0602` | 错误码或导出链接名冲突 |

不得用宿主 Python 异常回溯代替用户诊断；内部错误保留独立退出码并报告可重现输入。编译器不应自动执行源码、下载依赖或运行汇编中的命令。

L0 的文档交付不能替代以下 L1 实测，主计划仍以“测试集全部通过，编译出的内核模块能启动”为门槛：

1. 词法/语法/类型/初始化/模块/unsafe 的成功和失败用例，覆盖中文名称、错误位置、非穷尽 match、无效 ABI 及未支持特性。
2. 每种整数宽度、调试/发布溢出、边界、除法、移位、短路及求值顺序；触发 panic 的测试由独立进程/测试运行器验证。
3. 数组、普通/packed/4096 对齐结构体、嵌套布局、切片、枚举、可选值和错误结果的大小、偏移、表示；布局清单与汇编访问同一份数据。切片负例必须覆盖 `let a = [1, 2]; let s = a[..]; s[0] = 3;` 的只读赋值错误，以及从 `packed struct P { pad: u8, xs: [2]u64 }` 的可能非对齐 `xs` 字段直接创建切片的错误（即使位于 unsafe 块也拒绝）。正例同时覆盖 `let s: []T` 可修改已合法获得的可写元素、packed 字段复制到对齐数组后切片，以及通过裸指针的显式非对齐整数访问。
4. 正常块退出、嵌套循环、return、try 上的 defer 顺序；验证返回值先保存、清理后返回。
5. 独立手写汇编 ABI 探针双向调用，验证 0–8 个参数、窄整数、双字寄存器耗尽后的整项栈传参、栈对齐、被调用者保存、Win64 shadow space 和跨约定桥接。没有独立探针结果不能称为“ABI 已验证”。
6. 检查生成汇编无 red zone、无隐式 SIMD、未声明运行时符号或非法绝对寻址；内核高半区链接、RIP 相对数据引用与外部汇编互调后在 QEMU 启动。
7. 原子测试覆盖并发增量与比较交换竞争；volatile 验证访问宽度和次数。测试只证明覆盖的情况，不能据此宣称编译器内存安全。
