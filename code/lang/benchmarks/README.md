# 初始 L2 性能基准

`python tools/bench_dong.py` 编译并真实执行固定语料：u64 累加、LCG 依赖链、分支/位运算混合、指针数组求和和复制。最后两项属于同一内存类别，分别列出结果；每次记录真实后端，不从报告中删除。

2026-10-18 后续循环/内存优化复验：同一默认五内核、两次暖身、九对样本和原1.20阈值，安静运行 `build/benchmarks/run-1183f35a9f06/result.json` 全部通过：sum 0.974、LCG 0.999、mix 0.980、array_sum 0.951、array_copy 1.116。五项均使用 SSA；普通内存顺序/别名与真实读取故障语义另有原生保护页回归。这一有限集合通过，不扩大成“所有关键基准”的最终清单。下方失败基线及全部原始样本继续保留。

独立手写 NASM 参考使用相同算法、输入、前向循环规模和 SysV 调用边界。C 只生成输入、独立计算正确值与测时，不把 C 版本拿来当计时参考。默认每项两个暖身，九对样本，轮换测试顺序并交替 Dong/参考先后。判据在运行前固定为全部九样本的 Dong 中位耗时除以参考中位耗时，不超过原计划 1.20；保存每个原始耗时，不挑最快结果。

普通运行即使超限也保存 `passed:false` 并返回 0；`--check` 在超限时返回 1。构建、正确值、时钟、样本或源哈希失败返回 2。每次使用全新 `build/benchmarks/run-*`；原始 stdout/stderr、工具版本、命令、编译器/语料/汇编/对象/可执行文件哈希和逐函数后端均保留。

可用 `--iterations`、`--memory-words`、`--repeats` 明确调整工作规模；报告记录实际值。固定九样本和 1.20 阈值不可通过命令行降低。初始五个内核不是“所有关键基准”的最终清单，结果不等于完整 L2 或 L3 验收。

默认 `--measurement-context diagnostic`。只有停止并行构建/测试后才由操作者明确指定 `--measurement-context quiescent`；该字段记录操作者声明，工具不假装自动证明整个宿主完全空闲。每次封存本次实际编译器及语料源码实物，并在运行前后比较哈希。C 会在计时前后根据固定种子独立重建原输入，拒绝输入被改或复制结果错误。
