# 真实用户进程与 IPC 里程碑

2026-10-17。两个独立 ET_DYN ELF 经内核验证、随机加载到不同物理 CR3，使用真实 CPL3 IRET/SYSCALL/SYSRET 往返。`kernel/user/memory.dg` 管理私有表、用户 RAM、四页栈与两侧保护页；`kernel/user/runtime.dg` 分派句柄、端点、通知和共享数据对象。当前是受控 BSP 运行时，尚不能据此关闭完整 P4/P5。

实际验证结果：

| 配置 | 完成往返 | 实际系统调用 | 错误/权限拒绝 | 独立物理核对 |
| --- | ---: | ---: | --- | --- |
| XSAVE | 1,000,000 | 2,000,015 | 消息错误0，预期拒绝5 | 77次读取，通过 |
| FXSAVE | 1,000,000 | 2,000,015 | 消息错误0，预期拒绝5 | 77次读取，通过 |
| 生产入口 | 1,000 | 2,015 | 消息错误0，预期拒绝5 | 77次读取，通过 |

首个百万配置记录 TSC 差157,734,433,930、校准频率3,413,967,780Hz，换算46.202672108秒。环境为 Windows/QEMU TCG；此数字不代表 KVM 性能。完整字段、各配置实际耗时、命令、链接 ELF、原始串口及物理快照保存在 `build/test/p4-user/qemu/`。

宿主通过 QMP 暂停在实际完成入口，独立读取原 BootInfo、内核240B报告、用户页表和共享物理页，核对：两个独立24页表池；实际 ELF 代码逐字节相同；用户代码 RX、数据和栈 RW/NX、WB；四个用户栈保护页缺席；两个共享 PTE 解析到同一物理计数器。原有 ACPI 与 P3 的设备映射、定时器/控制器及抢占结果门禁也在同次启动继续执行。

用户程序逐次核对64B消息全部八个字，服务器更新共享计数器，客户端独立核对该值。句柄越权复制、关闭后旧代际、越界输入、RX输出和跨栈边界输入均实际拒绝。用户拷贝先验证完整范围和 RAM 所有权，再经受控 supervisor 别名访问；SMAP保持开启、AC为0，不直接借用未经验证的用户指针。

额外实际负控编译了仅在隔离目录修改的服务器：每条响应故意破坏第二个字。客体在第一轮消息返回后由客户端检测并失败，退出35；报告 `roundtrips=1,user_errors=1,error_code=0x04070004`，没有成功标记。构建失败不会算该负控通过。首次1,000轮烟测、上述三配置、真实坏服务器，共五次客体执行；另有一次符号命名冲突在启动客体之前被拒绝，历史记录保留。串口协议三项宿主测试验证乱序、截断、重复成功标记和伪造计数不能通过。

运行：`python tests/run_user_qemu.py --case normal`、`--case fxsave`、`--case production --rounds 1000`；实际负控：`python tests/run_user_negative_qemu.py`。

后续仍需通用进程创建/退出/故障隔离、完整 init/用户库、PCID 回收协议及 SMP 用户调度。当前同步直接交接使用单 BSP，每次切换加载 CR3，定时器在 P3 证明后停止。x87/SSE按现有 XSAVE/FXSAVE 契约保存；YMM/AVX2和持续抢占用户服务由后续阶段接入。P5 的独立驱动、FS、shell 与 P7 桌面并未在此里程碑验收。
